# 03 · 并行分支与合并

> 📚 阅读顺序 **7/14** · ◀ 上一节 [06-决策分支](06-决策分支.md) · ▶ 下一节 [08-会签](08-会签.md) · [目录](README.md)

> `fork` 让所有出边同时执行（多条并行推进路径），`join` 等待上游全部完成再放行。实现：`ForkNode` / `JoinNode` / `MergeBranchHandler`。

## 完整示例：并行审批两条线

```json
{
  "nodes": [
    { "id": "start", "type": "ingenious:start", "text": { "value": "发起" }, "properties": {} },
    { "id": "fork", "type": "ingenious:fork", "text": { "value": "并行" }, "properties": {} },
    { "id": "finance", "type": "ingenious:task", "text": { "value": "财务审核" }, "properties": { "assignee": "4" } },
    { "id": "hr", "type": "ingenious:task", "text": { "value": "人事审核" }, "properties": { "assignee": "5" } },
    { "id": "join", "type": "ingenious:join", "text": { "value": "汇合" }, "properties": {} },
    { "id": "boss", "type": "ingenious:task", "text": { "value": "领导审批" }, "properties": { "assignee": "2" } },
    { "id": "end", "type": "ingenious:end", "text": { "value": "结束" }, "properties": {} }
  ],
  "edges": [
    { "sourceNodeId": "start", "targetNodeId": "fork", "properties": {} },
    { "sourceNodeId": "fork", "targetNodeId": "finance", "properties": {} },
    { "sourceNodeId": "fork", "targetNodeId": "hr", "properties": {} },
    { "sourceNodeId": "finance", "targetNodeId": "join", "properties": {} },
    { "sourceNodeId": "hr", "targetNodeId": "join", "properties": {} },
    { "sourceNodeId": "join", "targetNodeId": "boss", "properties": {} },
    { "sourceNodeId": "boss", "targetNodeId": "end", "properties": {} }
  ]
}
```

运行表现：进入 `fork` 后 `finance` 与 `hr` 两个待办**同时出现**；先办结的等待，两个都办结后 `join` 放行，产生 `boss` 待办。

## 合并判定算法（MergeBranchHandler）

```
进入 join
  1. 沿 join 入边向上递归收集所有前置 TaskNode（遇到 fork 停止）
  2. 查询同实例内这些节点的 DOING 任务
  3. 全部为空 → 放行流转
     仍有 DOING → 等待（由后完成的任务触发重试）
```

## 要点与陷阱

| 要点 | 说明 |
|------|------|
| 各线独立办结 | fork 后每个并行任务各自出现在各自处理人的待办，互不阻塞 |
| 不要求边数对齐 | 合并以「上游任务全部办结」为准，fork 三出边两条到 join 也成立 |
| fork/join 无属性 | start/end/fork/join 均无额外业务属性，配置零负担 |
| 分支中可再嵌套 | 并行线内可以再放 decision / 会签节点，甚至另一组 fork/join |
| 别把 fork 用于会签 | 多人审同一件事用 [会签](08-会签.md)（perform_type=ALL），fork 是"多件事并行" |

## 并行线内嵌会签

一条并行线内部照样可以放会签节点——"财务线内部 3 人平行盖章，人事线 1 人审，两条线都完成后汇合"：

```json
{ "id": "fork", "type": "ingenious:fork" },
{ "id": "finance_cosign", "type": "ingenious:task",
  "properties": { "perform_type": "ALL", "assignee": "6,7,8",
    "field": { "countersign_type": "PARALLEL" } } },
{ "id": "hr_check", "type": "ingenious:task",
  "properties": { "assignee": "5" } }
```

边：`fork → finance_cosign`、`fork → hr_check`，两条线各自汇入 `join`。

## 调试观察点

| 观察什么 | 在哪看 |
|----------|--------|
| 并行任务是否都创建了 | 任务表：同 `process_instance_id`、不同 `task_name`、状态 DOING |
| join 为什么不放行 | 查上游各 TaskNode 是否还有 DOING 任务（MergeBranchHandler 判定依据） |
| 谁还没办 | 待办列表按实例过滤，对比 fork 各线的处理人 |
