# 07 · 任务调度（提醒/超时/自动办理/回调）

> 📚 阅读顺序 **11/14** · ◀ 上一节 [10-子流程](10-子流程.md) · ▶ 下一节 [12-AOP切面](12-AOP切面.md) · [目录](README.md)

> 架构：引擎只定义契约（`IScheduler` + 事件挂载点），插件提供常驻进程与执行器实现。

## 分层架构

```
引擎侧（packages/workflow）              插件侧（plugin/workflow）
IScheduler 接口              ←薄适配─    app/scheduling/TaskScheduler
scheduling/SchedulerProcessEventListener  →  TaskScheduleService（持久化 wf_process_schedule[_history]）
（task.start 事件挂载点）                  →  WorkflowSchedulerProcess（webman 常驻进程）
                                          →  executor/ 六类执行器
```

- 进程注册：`config/process.php` 中 `workflow-scheduler`（部署时必须启用）
- 业务代码注入 `IScheduler` 可主动 `schedule()` / `cancel()`

## 调度场景（ScheduleTypeEnum）

| 场景 | 值 | 触发 |
|------|-----|------|
| `PROCESS_EXPIRE_TIME` | 1 | 流程期望时间 |
| `PROCESS_TASK_EXPIRE_TIME` | 2 | 任务超时（`expire_time`） |
| `PROCESS_TASK_REMINDER_TIME` | 3 | 任务提醒（`reminder_time`） |
| `PROCESS_TASK_REPEAT_TIME` | 4 | 间隔重复（`reminder_repeat`） |
| `PROCESS_TASK_AUTO_EXECUTE` | 5 | 到时自动办理（`auto_execute`） |
| `PROCESS_TASK_CALLBACK` | 6 | 任务回调（`callback`） |
| `PROCESS_INSTANCE_START_REMINDER` | 7 | 流程启动消息提醒 |
| `PROCESS_INSTANCE_END_REMINDER` | 8 | 流程结束消息提醒 |
| `PROCESS_TASK_START_REMINDER` | 9 | 任务启动消息提醒 |
| `PROCESS_TASK_END_REMINDER` | 10 | 任务办结消息提醒 |

## 六类执行器（plugin/workflow app/scheduling/executor）

| 执行器 | 职责 |
|--------|------|
| `ScheduleExecutor` | 通用调度入口（按 scene 分发到下面各执行器） |
| `ReminderExecutor` | 待办提醒（站内/邮件/短信/webhook 四渠道） |
| `TimeoutExecutor` | 任务超时处理 |
| `AutoExecuteExecutor` | 自动办理（按默认意见办结） |
| `CallbackExecutor` | 任务回调类执行 |
| `ImmediateNotifyExecutor` | 即时通知（任务创建/转办等实时场景） |

## 配置片段

任务节点侧（json 属性触发调度挂载）：

```json
{
  "properties": {
    "reminder_time": "2026-09-20 09:00:00",
    "reminder_repeat": "3600",
    "expire_time": "2026-09-25 18:00:00",
    "auto_execute": "1",
    "callback": "App.Workflow.Handler.PayCallback"
  }
}
```

调度记录（`wf_process_schedule` 关键字段）：

```text
scene          场景（ScheduleTypeEnum）
business_id    幂等键 wf:instance:task:scene（ScheduleConst::businessId）
scheduled_at   计划执行时间
repeat_interval 重复间隔秒（0=不重复）
status         0待执行 1执行中 2成功 3失败 4已取消
channel_config 渠道覆盖（notify/mail/sms/webhook）
```

## 幂等与补偿

- 幂等键：`wf:{instanceId}:{taskId}:{scene}`，同一任务同场景重复挂载会覆盖/跳过
- 执行历史：每次执行写 `wf_process_schedule_history`（状态、结果、耗时），失败可按 status=3 排查补偿
- 引擎侧 `SchedulerProcessEventListener` 是骨架挂载点，宿主可基于事件总线实现自己的调度策略（不依赖插件进程）

## 实现自己的调度器

引擎契约只有两个方法，任何宿主都可替换实现：

```php
namespace madong\workflow\interface;

interface IScheduler
{
    /** 任务创建后按 params（含 reminder_time/expire_time/auto_execute/callback 等）挂调度计划 */
    public function schedule(string $taskId, string $processInstanceId, array $params = []): void;

    /** 任务办结/撤销时取消全部关联计划 */
    public function cancel(string $taskId): void;
}
```

```php
// 业务侧实现示例：直接抛进自己的队列
class QueueScheduler implements \madong\workflow\interface\IScheduler
{
    public function schedule(string $taskId, string $processInstanceId, array $params = []): void
    {
        Queue::push('wf-schedule', ['task_id' => $taskId, 'params' => $params]);
    }

    public function cancel(string $taskId): void
    {
        Queue::push('wf-schedule-cancel', ['task_id' => $taskId]);
    }
}
```

插件层的 `TaskScheduler` 就是该接口的完整生产实现（持久化 + 重试 + 渠道分发）。

## 排错指南

| 现象 | 检查 |
|------|------|
| 调度计划没生成 | 节点 json 是否配了时间属性；`workflow-scheduler` 进程是否在运行（`php webman status`） |
| 提醒没收到 | `wf_process_schedule` 该行 status：0 未执行（看 scheduled_at 是否已过）/ 3 失败（看 history 结果） |
| 同一提醒发多次 | 确认幂等键未变；`reminder_repeat` 配置是否就是想要的行为 |
| 自动办理没执行 | `auto_execute` 属性是否传到 params；AutoExecuteExecutor 需要默认意见配置 |
| 时间到了没触发 | 调度进程心跳与 Redis 连接；服务器时区与 `scheduled_at` 时区是否一致 |
