# 02 · 决策分支（判断）

> 📚 阅读顺序 **6/14** · ◀ 上一节 [05-任务节点](05-任务节点.md) · ▶ 下一节 [07-并行分支与合并](07-并行分支与合并.md) · [目录](README.md)

> 按表达式选择唯一一条出边，`DecisionNode::execute()` 遍历出边求值，命中即走（短路）。

## 完整示例：金额分档审批

```json
{
  "nodes": [
    { "id": "start", "type": "ingenious:start", "text": { "value": "发起" }, "properties": {} },
    { "id": "check", "type": "ingenious:decision", "text": { "value": "金额判断" }, "properties": { "expr": "" } },
    { "id": "lead", "type": "ingenious:task", "text": { "value": "主管审批" }, "properties": { "assignee": "1" } },
    { "id": "manager", "type": "ingenious:task", "text": { "value": "经理审批" }, "properties": { "assignee": "2" } },
    { "id": "end", "type": "ingenious:end", "text": { "value": "结束" }, "properties": {} }
  ],
  "edges": [
    { "sourceNodeId": "start", "targetNodeId": "check", "properties": {} },
    { "sourceNodeId": "check", "targetNodeId": "manager", "properties": { "expr": "#f_amount>=1000" } },
    { "sourceNodeId": "check", "targetNodeId": "lead", "properties": { "expr": "" } },
    { "sourceNodeId": "lead", "targetNodeId": "end", "properties": {} },
    { "sourceNodeId": "manager", "targetNodeId": "end", "properties": {} }
  ]
}
```

发起时传入变量 `{ "f_amount": 2500 }` → 走 `manager` 分支。

## 表达式语法（DefaultExpressionEngine）

| 语法 | 示例 | 说明 |
|------|------|------|
| 变量 | `#f_amount` 或 `${f_amount}` | 求值时替换为实例变量真实值 |
| 比较 | `==  !=  >  >=  <  <=` | 替换后为表达式则求值 |
| 算术 | `+ - * / ( )` | 如 `#f_day*8>40` |
| 逻辑 | `&` `|` `!` | 如 `#f_urgent==true&f_day>3` |
| 字符串 | `#status=='true'` | 注意替换后是字面量，比较字符串需引号 |

求值规则：替换变量后，若结果是纯算术/比较表达式则计算返回；否则原样返回字符串。结果转 bool：`true/1` → true，`false/0/''` → false，其余 `(bool)` 转换。

## 多变量组合示例

```json
{ "properties": { "expr": "#f_amount>=10000|#f_urgent=='true'" } },
{ "properties": { "expr": "#f_amount*#f_qty>50000" } },
{ "properties": { "expr": "#f_type=='travel'&f_day>3" } }
```

| 表达式 | 语义 |
|--------|------|
| `#f_amount>=10000\|#f_urgent=='true'` | 金额超万**或**加急 → 高级审批 |
| `#f_amount*#f_qty>50000` | 单价×数量组合计算 |
| `#f_type=='travel'&f_day>3` | 类型+天数组合条件 |

## 决策两条路线怎么选

| | 出边表达式 | `handle_class` |
|---|-----------|----------------|
| 改路由需要 | 改流程 json（重新发布新版本） | 改 php 类（即时生效） |
| 适合 | 规则简单稳定、设计器可视化可配 | 需查库/调接口的复杂规则 |
| 可读性 | 设计器上直接看到 | 逻辑藏在类里，需文档说明 |

实践建议：简单阈值用表达式；"按组织架构找人审"类规则用 `handle_class`。

## 与会签组合：按票数路由

会签节点后接决策节点，用 `cs_*` 计数变量分流（变量说明见 [08-会签](08-会签.md)）：

```json
{ "sourceNodeId": "cosign", "targetNodeId": "check", "properties": {} },
{ "sourceNodeId": "check", "targetNodeId": "archive", "properties": { "expr": "#cs_cosign_nrOfCompleted==3" } },
{ "sourceNodeId": "check", "targetNodeId": "review",  "properties": { "expr": "" } }
```

## 兜底与默认分支

```text
出边遍历求值，命中即走（短路）
├─ 一条边 expr 留空          → 作为 else 默认分支
├─ 全部不满足且无默认边      → 抛 NodeException（实例不静默卡死）
└─ 节点 properties.expr     → 很少直接用，一般配在出边
```

## 自定义决策类

复杂路由逻辑（查库/调接口）用 `handle_class`，返回目标**节点名**：

```json
{
  "id": "check",
  "type": "ingenious:decision",
  "properties": { "handle_class": "App.Workflow.Handler.RouteHandler" }
}
```

```php
namespace App\Workflow\Handler;

use madong\workflow\context\ExecutionContext;

class RouteHandler
{
    /**
     * 返回要流转到的节点名
     */
    public function route(ExecutionContext $ctx, mixed $args): string
    {
        $amount = (float) $ctx->getVariable('f_amount', 0);
        return $amount >= 10000 ? 'manager' : 'lead';
    }
}
```
