# 05 · 运行时加签与协办（嵌套会签）

> 📚 阅读顺序 **9/14** · ◀ 上一节 [08-会签](08-会签.md) · ▶ 下一节 [10-子流程](10-子流程.md) · [目录](README.md)

> 流程已在办理中时动态扩展参与人。由**插件层**实现（`wf_process_cosign` 独立协办表），引擎在任务办结时做三态判断（`TaskNode::execute()`）。

## 三种模式

| 模式 | 行为 | 常量 |
|------|------|------|
| 前加签（会签组） | 先让加签人办，全部办结后回到发起人终审 | `KIND_COUNTERSIGN` + `MODE_BACK_TO_ME` |
| 后加签 | 当前办结后先流转给加签人，办结后继续原流程 | `KIND_ADD_SIGN` + `MODE_FORWARD` |
| 运行时会签 | 把加签人并入当前任务的会签组 | `KIND_COUNTERSIGN` + 并行/串行 |

## 调用入口

```php
// 插件服务层：plugin/workflow app/engine/service/ProcessTaskService.php
$service->addSignTasks(
    taskId: '任务的ID',
    userIds: ['7', '8'],          // 被加签人
    operator: '6',                // 发起人（须为任务办理人）
    comment: '请补充财务意见',
    mode: ProcessCosign::MODE_BACK_TO_ME,   // 1=回我终审 2=流转后继续
    order: ProcessCosign::ORDER_PARALLEL,   // 0=并行 1=串行
    kind: ProcessCosign::KIND_COUNTERSIGN,  // 1=加签 2=会签组
);
```

前端入口：待办页「加签」按钮 → `POST /adminapi/wf/operation/addSign`。

## 请求/响应链路

```
前端待办页
  → POST /adminapi/wf/operation/addSign { task_id, user_ids, comment, mode, order, kind }
  → 插件 ProcessController::addSign
  → ProcessTaskService::addSignTasks（校验办理人身份/去重 → 写 wf_process_cosign → 产生协办任务）
  → 协办任务即时出现在被加签人待办 + WebSocket 徽标推送
  → 协办人逐个办结（POST /adminapi/wf/operation/agree）
  → 锚点任务按三态判断回到待办或流转
```

## 任务表数据变化示意

前加签（张三=6 办结时拉李四=7、王五=8，MODE_BACK_TO_ME）：

```
wf_process_cosign 新增两行：
  anchor_task_id=锚点任务  cosign_task_id=新任务A(李四)  status=PENDING
  anchor_task_id=锚点任务  cosign_task_id=新任务B(王五)  status=PENDING

wf_process_task 新增两个 is_cosign=1 的任务（李四/王五 待办）
锚点任务保持 FINISHED（张三已办结，等待协办结果驱动 RESUME）
```

协办人办结 → 对应行 status 置 SUCCESS → 全部 SUCCESS 时锚点产生 RESUME 待办（发起人终审）。

## 引擎三态判断

锚点任务（被加签的原任务）办结时，引擎查询协办表决定走向：

| 状态 | 语义 | 引擎行为 |
|------|------|----------|
| `COSIGN_WAIT` | 协办组尚未全部办结 | 锚点任务等待，不流转 |
| `COSIGN_RESUME` | 前加签组办结，待发起人终审 | 锚点任务回到待办 |
| `FLOW`（无协办挂起） | 后加签组办结 / 锚点终审完成 | 正常执行后续边 |

```
前加签时序（MODE_BACK_TO_ME）
张三办结 → 查协办表 COSIGN_WAIT（李四/王五未办）→ 等待
        → 李四办结、王五办结 → 组完成 → 锚点 RESUME → 张三待办（终审）
        → 张三再次办结 → FLOW → 流转下一节点

后加签时序（MODE_FORWARD）
张三办结 → 产生加签任务（李四）→ 李四办结 → FLOW → 流转下一节点
```

## 关键约束

| 约束 | 说明 |
|------|------|
| 仅任务办理人可发起 | 非参与人/非办理人抛异常 |
| 去重 | 排除已在办理中（参与人 + 同节点 DOING 办理人 + 待办协办明细）与发起人本人 |
| 协办任务不污染计数 | 协办成员任务带 `is_cosign` 标记，办结**直接结束不触发节点流转**，定义级会签 `nrOf*` 不受影响 |
| 徽标实时推送 | 协办任务产生/办结即时推送 WebSocket 徽标（插件 WorkflowBadgePushListener） |
| 旧数据兼容 | 无协办记录的旧实例走 sibling 兜底（同节点仍有 DOING 兄弟任务则等待），行为不变 |

## 数据表

| 表 | 职责 |
|----|------|
| `wf_process_cosign` | 协办明细：锚点任务、协办任务、发起人、mode/order/kind、状态 |
| `wf_process_task` | 协办成员任务（`is_cosign=1`）与锚点任务共存 |
