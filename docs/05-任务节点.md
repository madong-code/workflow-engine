# 01 · 任务节点

> 📚 阅读顺序 **5/14** · ◀ 上一节 [流程能力总览](04-流程能力总览.md) · ▶ 下一节 [06-决策分支](06-决策分支.md) · [目录](README.md)

> 最常用的节点：进入即产生待办任务，全部办结后沿出边流转。实现：`TaskNode` + `CreateTaskHandler`。

## 基础示例

```json
{
  "id": "approve",
  "type": "ingenious:task",
  "text": { "value": "部门审批" },
  "properties": {
    "assignee": "${manager}",
    "task_type": "Major",
    "perform_type": "ANY"
  }
}
```

## 处理人解析链

进入节点后按以下顺序解析处理人（`CreateTaskHandler`）：

| 优先级 | 属性 | 说明 |
|--------|------|------|
| 1 | `assignee` | 直接指定，支持 `${变量}` 与 `node.var`（引用上游节点变量） |
| 2 | `assignment_handler` | 分配器类（点号形式），运行时动态计算处理人 |
| 3 | `candidate_users` / `candidate_groups` | 候选人 / 候选组名单 |
| 4 | `candidate_handler` | 候选解析类（点号形式），如按组织架构展开 |

示例：分配器动态指定处理人

```json
{
  "properties": {
    "assignment_handler": "App.Workflow.Handler.LeaderAssignHandler",
    "task_type": "Major"
  }
}
```

```php
namespace App\Workflow\Handler;

use madong\workflow\interface\model\IProcessInstance;
use madong\workflow\util\Accessor;

class LeaderAssignHandler
{
    /**
     * 返回处理人标识
     */
    public function handle(IProcessInstance $instance, mixed $args): string
    {
        $dept = Accessor::getValue($instance, 'variable.leader_id');
        return (string) ($dept ?: '1');
    }
}
```

## 关键属性

| 属性 | 值 | 说明 |
|------|-----|------|
| `task_type` | `Major` / `Minor` / `Cc` | 主任务（待办）/ 传阅 / 抄送 |
| `perform_type` | `ANY` / `ALL` | 任一人办结即流转 / 会签（见 [08-会签](08-会签.md)） |
| `form` | url | 任务处理表单地址 |
| `group_key` | 字符串 | 候选组 key |
| `reminder_time` / `reminder_repeat` | 时间 / 间隔 | 提醒与重复提醒（需插件调度进程） |
| `expire_time` | 时间 | 超时时间（需插件调度进程） |
| `auto_execute` | 标记 | 到时自动办理 |
| `callback` | 类（点号形式） | 任务回调类 |
| `ext` | 任意 | 扩展数据，引擎透传 |

## 任务生命周期

```
进入节点 → 解析处理人 → 创建任务(actor 落库) → 待办(DOING)
        → 办结(FINISHED) → 节点全部任务办结? → 是: 沿出边流转
                                          → 否: 等待
```

## assignee 写法对比

| 写法 | json | 运行时 |
|------|------|--------|
| 字面量 | `"assignee": "6"` | 固定处理人 6 |
| 实例变量 | `"assignee": "${manager_id}"` | 启动时传 `{ "manager_id": "2" }` |
| 上游节点变量 | `"assignee": "lead.handler"` | 取 lead 节点写入的 `handler` 变量 |
| 混合（多候选） | `"assignee": "6,7,8"` | 每人一个任务（ANY 任一办结即流转；ALL 走会签） |

发起示例：

```php
$engine->startProcess('wf-leave', '6', [
    'f_day'      => 2,
    'manager_id' => '2',     // 供 "assignee": "${manager_id}" 使用
]);
```

## 候选 + 分配器组合

```json
{
  "properties": {
    "candidate_groups": "finance,audit",
    "candidate_handler": "App.Workflow.Handler.DeptUserExpandHandler",
    "perform_type": "ANY"
  }
}
```

`candidate_groups` 给出候选范围，`candidate_handler` 运行时把组展开为具体用户列表——适合"按当前单据部门找人"。

## 常见问题

| 现象 | 排查 |
|------|------|
| 任务没产生 | 检查上游 decision 是否所有出边都不满足（抛 NodeException 不会静默） |
| 处理人为空 | `assignee` 表达式变量未传 → 启动 vars 里补；或改配 `assignment_handler` 兜底 |
| 想改处理人 | 用插件层转办/委托功能（运行时能力），不改流程定义 |
| 任务一直 DOING | 会签节点看完成条件；并行节点看 join 上游是否还有 DOING |

> 会签、加签等高级用法见 [08-会签](08-会签.md) 与 [09-运行时加签与协办](09-运行时加签与协办.md)。
