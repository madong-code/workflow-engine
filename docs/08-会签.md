# 04 · 会签

> 📚 阅读顺序 **8/14** · ◀ 上一节 [07-并行分支与合并](07-并行分支与合并.md) · ▶ 下一节 [09-运行时加签与协办](09-运行时加签与协办.md) · [目录](README.md)

> `perform_type=ALL` 即会签节点：进入时按参与者名单一次性创建多实例任务，满足完成条件后节点才向后流转。实现：`TaskNode` + `CountersignHandler`。

## 并行会签示例

```json
{
  "id": "cosign",
  "type": "ingenious:task",
  "text": { "value": "三人会签" },
  "properties": {
    "perform_type": "ALL",
    "assignee": "6,7,8",
    "field": {
      "countersign_type": "PARALLEL",
      "countersign_completion_condition": "#nrOfCompletedInstances==3"
    }
  }
}
```

## 串行会签示例

```json
{
  "properties": {
    "perform_type": "ALL",
    "assignee": "6,7,8",
    "field": {
      "countersign_type": "SEQUENTIAL",
      "countersign_completion_condition": "#nrOfCompletedInstances==3"
    }
  }
}
```

串行模式按 operatorList 顺序逐个产生任务，第 N 位办结后才产生第 N+1 位的任务。

## 会签类型对比

| `countersign_type` | 任务产生方式 | 典型场景 |
|--------------------|--------------|----------|
| `PARALLEL`（默认） | 全部同时产生，任意顺序办结 | 多部门并行盖章 |
| `SEQUENTIAL` | 逐个产生，按名单顺序 | 层级签批 |

## 完成条件

| `countersign_completion_condition` | 语义 |
|-------------------------------------|------|
| `#nrOfCompletedInstances==3` 等表达式 | 求值 true 即合并（不等全部办完） |
| `#nrOfCompletedInstances/#nrOfInstances>=0.5` | 过半通过 |
| `ONE_VOTE_VETO` | 一票否决：任一人否决（`cs_disagree` 置位）即结束会签 |
| 留空 | 并行：无 DOING 任务即完成；串行：最后一位办结即完成 |

## 引擎内部变量

会签过程自动维护两组变量：

**私有小写变量**（前缀 `cs_` + 节点名，持久化到实例变量）：

| 变量 | 说明 |
|------|------|
| `cs_{node}_operatorList` | 参与者名单 |
| `cs_{node}_loopCounter` | 当前操作人在名单中的序号（串行推进用） |
| `cs_{node}_nrOfCompleted` | 已完成票数（每次办结 +1） |

**标准计数变量**（求值条件表达式时自动注入上下文）：

| 变量 | 说明 |
|------|------|
| `nrOfInstances` | 总票数 |
| `nrOfActiveInstances` | 未完成票数 |
| `nrOfCompletedInstances` | 已完成票数 |

## 一票否决示例

```json
{
  "properties": {
    "perform_type": "ALL",
    "assignee": "6,7,8",
    "field": {
      "countersign_type": "PARALLEL",
      "countersign_completion_condition": "ONE_VOTE_VETO"
    }
  }
}
```

> 与 [09-运行时加签与协办](09-运行时加签与协办.md) 的关系：定义级会签票数由名单决定；运行时动态加的人走协办表，**不进入**本节点的定义级计数。

## 票数变量的完整生命周期

以 3 人并行会签（节点名 `cosign`）为例：

```
进入节点
  → 创建 3 个任务（6/7/8 各一票）
  → 变量写入：cs_cosign_operatorList = "6,7,8"
             nrOfInstances=3, nrOfActiveInstances=3, nrOfCompletedInstances=0

6 办结 → cs_cosign_nrOfCompleted=1 → nrOfCompletedInstances=1
         条件 "#nrOfCompletedInstances==3" 求值 false → 等待
7 办结 → nrOfCompletedInstances=2 → false → 等待
8 办结 → nrOfCompletedInstances=3 → true → 合并流转下一节点
```

串行会签则每步还会更新 `cs_cosign_loopCounter`（当前应办理人在名单中的序号），由它驱动下一票任务的创建。

## 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 完成条件一直不满足 | 表达式里变量名写错（`#nrOfCompletedInstances` 是引擎注入的固定名，不能自定义） |
| 只有一票就流转了 | 完成条件写成了 `>=1` 或留空且任务被外部办结 |
| 少数服从多数怎么配 | `"#nrOfCompletedInstances/#nrOfInstances>=0.5"`（表达式支持算术） |
| 一票否决后其余票怎么办 | 引擎结束会签合并流转，未办任务由引擎兜底清理，不产生幽灵待办 |
| 会签中想加人 | 走[运行时加签](09-运行时加签与协办.md)，协办不占定义级票数 |

## 会签 + 超时催办组合

会签节点配上调度属性，超时未办的票自动催办（需插件调度进程，见 [11-任务调度](11-任务调度.md)）：

```json
{
  "properties": {
    "perform_type": "ALL",
    "assignee": "6,7,8",
    "field": { "countersign_type": "PARALLEL", "countersign_completion_condition": "#nrOfCompletedInstances==3" },
    "reminder_time": "2026-09-20 09:00:00",
    "reminder_repeat": "86400",
    "expire_time": "2026-09-30 18:00:00"
  }
}
```
